# Go-live responsibilities (RACI)

R = responsible (does it), A = accountable (owns the result, one per row), C = consulted, I = informed.

| Activity | CS (go-live lead) | Sales | Engineering | Product | Customer |
|---|---|---|---|---|---|
| Complete the handover | C | A, R | I | I | C |
| Agree price, date and success criteria in writing | C | A, R | I | I | R |
| People discovery interviews | A, R | I | I | I | C |
| Role-change message to staff | R (draft) | I | I | I | A (sends it) |
| Workflow map and human/AI split | A, R | I | C | I | C |
| Configuration | A, R | I | C | I | C |
| Integrations and two-way sync | C | I | A, R | I | C |
| Enterprise readiness checks (SSO, SCIM, access model, audit logs) | R | I | A, R | C | C |
| Data processing agreement and retention settings | C | R | C | I | A |
| Test suite and gate | A, R | I | C | C | C |
| Go/no-go decision | R | I | R | I | A |
| Hypercare and log reviews | A, R | I | C | I | C |
| Incident response | A, R | I | R | C | C |
| Product bugs and feedback | R (raise) | I | R (fix) | A (prioritise) | I |
| Value review against baseline | A, R | C | I | I | C |
| Next stage or expansion | R | A | I | C | C |

## Notes

- I own the go-live end to end, but I don't own sales, security engineering or procurement. Where those decide, I make sure the decision is made in time.
- The customer is accountable for the go/no-go, because it's their business and their staff. I make the recommendation.
